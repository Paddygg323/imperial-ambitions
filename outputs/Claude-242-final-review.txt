## Code review

**The four previously-reported issues are genuinely fixed**, verified by reading the actual files:

1. **Canonical save policy** — `game/save-policy.mjs` defines `SAVE_SLOT`/`MAX_SAVE_BYTES`; `android/scripts/build.py:32-36` regex-extracts both constants from that file and writes `generated/SavePolicy.java`, which `MainActivity.java` references (`SavePolicy.SLOT`, `SavePolicy.MAX_BYTES`). Single source of truth confirmed.
2. **UTF-8 byte-size enforcement** — `validateSaveSize` uses `TextEncoder().encode(value).byteLength`; `MainActivity.writeSave`/`exportSave` independently check `json.getBytes(UTF_8).length` against the same generated constant. Both sides agree.
3. **Turn snapshot failures** — `app.mjs:475`: the `-previous` snapshot write is wrapped in try/catch that `toast`s *"The turn has not advanced: …"* and `break`s before `beginTurn` ever runs. Confirmed the turn literally cannot advance on a snapshot failure.
4. **Archive-without-reading + honest cache export** — `MainActivity.archiveSave` only renames base/`.bak`/`.new` files (no read), rolls back partial renames on failure, and refuses to clobber an existing target. `save-recovery.mjs` separately relabels the export button to "Export cached copy" and states explicitly *"The original device file is unreadable… recovery will preserve the original device file separately before replacing it"* when `failure.raw===null`. This is correctly non-destructive and honestly labeled.

### New blocking defect: Android Back is a dead end during two real in-game states

`MainActivity.handleBack()` injects:
```js
if(d.dispatchEvent(e))d.close(); return true;
```
`return true` executes **unconditionally**, regardless of whether the dialog actually closed. On the Java side, `"true".equals(closed)` suppresses the "Leave the game?" confirmation whenever *any* `<dialog>` is open — even one whose `cancel` listener called `preventDefault()` specifically to stay open.

Two live code paths do exactly that:
- `save-recovery.mjs:52` — `dialog.addEventListener('cancel',e=>e.preventDefault())` on the recovery dialog.
- `app.mjs:483` — the main `#panel` dialog prevents cancel whenever `state.market` is truthy (i.e., during the ordinary end-of-turn market/trade flow).

In both states, pressing Android Back produces **no effect and no feedback**: the dialog stays open, and no "leave game" prompt appears either. This is worst during save-recovery — a user confused about a corrupted save gets a silently unresponsive Back button at exactly the moment they're most likely to reach for it. (Home/recents still work; this isn't a hard app lock, but the in-app Back affordance is broken in two reachable states.)

### Evidence-trust gap on the "native storage test"

`Android-emulator-storage.txt` (and the two sibling `.txt` logs) are bare `INSTRUMENTATION_RESULT` text claiming unreadable-file handling, UTF-8 rejection, and path-allowlist checks passed. I searched the entire mirror: **there is no `androidTest` source tree, no instrumentation test class, anywhere in this snapshot** — `android/` contains only `AndroidManifest.xml`, `build.py`, `bundle.py`, and `MainActivity.java`. I can't verify these logs correspond to any test code that actually exercises `archiveSave`'s rollback or `campaignFile`'s regex allowlist; they're unfalsifiable from what's shipped here. Treat them as unverified claims, not confirmed results.

### Diplomacy Power/Trade bars — accurate as described

`diplomacy-map.mjs:29-34`: `power` sums `strategicRegimentRating`/`strategicNavyRating` over live HP>0 units, gated by `s.nations[id]` so minors render `'—'` with the tooltip *"Minor-nation forces require scouting"* instead of a fabricated bar. `traded` sums `s.reports` filtered to `kind==='trade' && nation===s.player`. This matches the stated design exactly — no deception found here.

## Bottom line

No blocking regression in the four previously-fixed areas — they hold up under direct reading. The one real blocking-ish defect I found is new: the **Android Back button silently does nothing** during save-recovery and during the market/trade panel, which matters most exactly when a user is worried about their save. The native-storage test log is unverifiable from what's in this mirror (no test source present). Visual direction is a legitimate, coherent upgrade on the original's chrome for the two screens with real reference art (diplomacy, engineer), with named gaps (sprite repetition vs. painterly tiles, washed-out relation-map palette, research panel's lighter ornamentation); the fourth screenshot (`map-915.png`) isn't usable evidence at all since it isn't a capture of this app.
